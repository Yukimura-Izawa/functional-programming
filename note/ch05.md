# 05 逐次プログラム

## 概要

### ストーリー

Mapで関数を引数にしたり、宣言型は理解できた
その時ありえるケースとしては、mapのfがx->List[]が出る場合、
f(x)がlistだと、map(f, List) = List[List[]]みたいになる
この処理をどうやるのか？

例

```
f(x) = {√x, -√x}        f(4) = {2, -2}
g(y) = {y+1, y-1}
```

Listの入れ子を解消するものとしてflattenを使う
さらに入れ子構造でも逐次計算をできるようにしたものはflatmapを使う
flatmapはまさにflattenとmapを合わせたものでそれぞれの意味が理解できれば自然に理解できる

さらにflatmapの処理を連続で行う(合成関数的な処理)の時、flatmapの入れ子構造みたいになる
まさにイメージはz=g(f(x))
これは見難いので、for内包表記を使う

例

```scala
for {
  x <- xs
  y <- f(x)
  z <- g(y)
  if z > 0          // z が正の道筋だけ残す
} yield (x, z)
```

内包表記の内側で条件についても表記することができる

ここで便利な内部に条件を含むfor内包表記がある。
要素が0個か1個なのか？ 結果がないことを、null や例外（プログラムが止まる）ではなく、普通の値（None）として扱える
これは便利だということでoptionという型とした。

### ストーリーまとめ

1. map を使うと、f がリストを返す場合に `List[List[]]` が生まれる
2. それを `List[]` として扱いたい（段をつなげたい）ので、flatten と flatMap が登場する
3. flatMap を連続で使う逐次処理（合成関数的な処理）を愚直に書くと、`flatMap(flatMap(...))` という `z = g(f(x))` のような入れ子になる
4. これは読みにくいので for 内包表記がある。内部に条件（if）も入れられる
5. flatMap と for は List 専用ではなく、flatMap を持つ型なら使える（Set、Option）
6. 特に「結果が0個か1個」は「結果がないかもしれない計算」としてよく出てくる → Option という型がある。途中で None になれば全体が None になる

## flatten：入れ子を1段つぶす

型と定義

- 引数：リストのリスト `List[List[A]]`
- 戻り値：1段平らにしたリスト `List[A]`

処理

```
flatten([])         = []
flatten(xs :: rest) = xs ++ flatten(rest)
```

具体例

```
flatten([[1, 10], [2, 20], [3, 30]]) = [1, 10, 2, 20, 3, 30]
flatten([[1], [], [2, 3]])           = [1, 2, 3]      ← 空リストは消える
```

## flatMap：多価関数を繋げる

基本mapのfがA->Bではなく、A->List[B]になった版

| | f の型 | 全体の入出力 | 結果の長さ |
|---|---|---|---|
| map | `A -> B`（1要素から1つの値） | `List[A] -> List[B]` | 必ず元と同じ |
| flatMap | `A -> List[B]`（1要素からリスト） | `List[A] -> List[B]` | 変わりうる（0個・1個・複数個） |

比較

```
map(f, [])            = []
map(f, x :: rest)     = f(x) :: map(f, rest)

flatMap(f, [])        = []
flatMap(f, x :: rest) = f(x) ++ flatMap(f, rest)
```

具体的な処理の流れ

f(x) = [x, x*10] として、

```
flatMap(f, [1,2,3])
= [1,10] ++ flatMap(f, [2,3])
= [1,10] ++ [2,20] ++ flatMap(f, [3])
= [1,10] ++ [2,20] ++ [3,30] ++ []
= [1,10,2,20,3,30]
```

Rustでは

Rust では flat_map という名前。f はリストの代わりに「イテレータにできるもの」（Vec など）を返す。

```rust
let xs = vec![1, 2, 3];
let nested: Vec<Vec<i32>> = xs.iter().map(|&x| vec![x, x * 10]).collect();
// [[1, 10], [2, 20], [3, 30]]

let flat: Vec<i32> = xs.iter().flat_map(|&x| vec![x, x * 10]).collect();
// [1, 10, 2, 20, 3, 30]
```

## for内包表記

読み書きしやすくするための記法

例題

```
xs = {4, 9}
f(x) = {√x, -√x}
g(y) = {y+1, y-1}

{ (x, z) | x ∈ xs, y ∈ f(x), z ∈ g(y) }
```

flatmapの入れ子で書く

```
flatMap(x =>
  flatMap(y =>
    map(z => (x, z), g(y)),
  f(x)),
xs)
```

これでは見難いので、少し簡略化してみる

```
flatMap(A, xs)
A(x)    = flatMap(y => B(x, y), f(x))
B(x, y) = map(z => (x, z), g(y))
```

更なる詳細

```
flatMap(A, [4, 9]) = A(4) ++ A(9)

A(4)     = flatMap(y => B(4, y), [2, -2])
         = B(4, 2) ++ B(4, -2)
B(4, 2)  = map(z => (4, z), [3, 1])   = [(4, 3), (4, 1)]
B(4, -2) = map(z => (4, z), [-1, -3]) = [(4, -1), (4, -3)]

A(4) = [(4, 3), (4, 1), (4, -1), (4, -3)]

A(9) = B(9, 3) ++ B(9, -3)
     = [(9, 4), (9, 2)] ++ [(9, -2), (9, -4)]
     = [(9, 4), (9, 2), (9, -2), (9, -4)]

A(4) ++ A(9) = [(4,3), (4,1), (4,-1), (4,-3), (9,4), (9,2), (9,-2), (9,-4)]
```

これでは難しいし理解しにくいので、for内包表記

```scala
for {
  x <- xs          // xsはリストだけど、全部の要素について1つずつ取り出す
  y <- f(x)        // f(x)はリストになるのだが、その要素を取り出しyとする
  z <- g(y)        // g(y)もリストだが、その要素をzとする
} yield (x, z)     // x->zって道筋
```

| | 普通の関数 | List を返す関数 |
|---|---|---|
| 入れ子（内側から読む） | `g(f(x))` | `flatMap(x => flatMap(g, f(x)), xs)` |
| 途中に名前を付けて順に書く | `y = f(x)`<br>`z = g(y)` | `for { x <- xs; y <- f(x); z <- g(y) } yield z` |
| 点を書かない合成 | `g∘f` | 別の道具（クライスリ合成）。for 内包表記ではない |

for 内包表記は x、y、z の全部に名前を付けるので、最後の yield (x, z) のように前の段の値を後で使える

## for内包表記の内側で条件を使う

集合の内包的記法で、条件を後ろに付け足すのと同じ発想

```
{ (x, z) | x ∈ xs, y ∈ f(x), z ∈ g(y), z > 0 }
```

書き方

条件を if で1行足す

```scala
for {
  x <- xs
  y <- f(x)
  z <- g(y)
  if z > 0          // z が正の道筋だけ残す
} yield (x, z)
```

条件なしの結果は `[(4,3), (4,1), (4,-1), (4,-3), (9,4), (9,2), (9,-2), (9,-4)]`
この if を付けると `[(4,3), (4,1), (9,4), (9,2)]` になる

中ではfilterに置き換わるということが行われている
（if は filter に書き換わります。filter の引数と戻り値は次のとおりです。）

- 引数：条件の関数 `p: A -> Boolean` とリスト
- 戻り値：p が true になる要素だけを残したリスト

```
flatMap(x =>
  flatMap(y =>
    map(z => (x, z), filter(z => z > 0, g(y))),   ← g(y) を先に絞る
  f(x)),
xs)
```

ここの考え方で大切なのは要素が0個か1個なのか？ 結果がないことを、null や例外（プログラムが止まる）ではなく、普通の値（None）として扱える

```scala
def keepPositive(z: Int): List[Int] =
  if (z > 0) List(z) else List()     // 条件を満たせば [z]、満たさなければ []

for {
  x <- xs
  y <- f(x)
  z <- g(y)
  p <- keepPositive(z)    // 普通の「<-」の段として足すだけ
} yield (x, p)
```

これは沢山使うのでoptionというものとして型として残す

```scala
def keepPositive(z: Int): Option[Int] =
  if (z > 0) Some(z) else None
```

Option は List と同じく型
keepPositive のような関数は、今後も自分で定義する
変わるのは戻り値の型で、`List[Int]` の代わりに `Option[Int]` を返すようになる

## Option

値のある時にそれを返し、ないときはNoneを返す
Option が用意してくれるのは、次の2つ

- 「最大1個」を保証する型そのもの
- その型に flatMap と map が定義されていること（だから for 内包表記で使える）

Rustでは値のある時に値を返し、それ以外の時Noneを返す。
（ちなみにエラーを返すのは `Result<T, E>`。値がある時 `Ok(T)`、ない時 `Err(エラー情報)`）

Listの型との違い

| List | Option |
|---|---|
| `[]` | `None` |
| `[x]` | `Some(x)` |
| `flatMap(f, []) = []` | `None` に flatMap → `None` |
| `flatMap(f, [x]) = f(x)` | `Some(x)` に flatMap → `f(x)` |

```scala
def sqrtOpt(x: Double): Option[Double] =
  if (x >= 0) Some(math.sqrt(x)) else None

for {
  a <- "16".toIntOption      // Some(16)。"abc" なら None
  b <- sqrtOpt(a)            // Some(4.0)。a が負なら None
} yield b
// "16" → Some(4.0)、"-4" → None、"abc" → None
```

Optionはまさにrustでよく出てくるもの

```rust
fn sqrt_opt(x: f64) -> Option<f64> {
    if x >= 0.0 { Some(x.sqrt()) } else { None }
}

fn parse_and_sqrt(s: &str) -> Option<f64> {
    let a: i32 = s.parse().ok()?;      // 失敗したらここで None を返して終わる
    let b = sqrt_opt(a as f64)?;       // 同上
    Some(b)
}
```

## Set

flatMap と for 内包表記は List 専用ではないものの例の一つ。optionと別の例。

Set とは

数学の集合と同じで、次の2つの性質を持つ入れ物

- 重複がない：同じ値は1つしか入らない
- 順番に意味がない：`{1, 2}` と `{2, 1}` は同じ

Listとの違い

```scala
Set(1, 2, 2, 3)   // → Set(1, 2, 3)。重複は自動で消える
List(1, 2, 2, 3)  // → List(1, 2, 2, 3)。そのまま
```

他の違いとして、リストの要素をつなげるではなく、和集合となる
Set の flatMap の引数と戻り値は、List と同じ形

- 引数：関数 `f: A -> Set[B]` と `Set[A]`
- 戻り値：`Set[B]`

例

```scala
// List で計算
for {
  x <- List(1.0)
  y <- List(math.sqrt(x), -math.sqrt(x))
  z <- List(y + 1, y - 1)
} yield z
// → List(2.0, 0.0, 0.0, -2.0)    道筋ごとに1つずつ。0 が2回

// Set で計算
for {
  x <- Set(1.0)
  y <- Set(math.sqrt(x), -math.sqrt(x))
  z <- Set(y + 1, y - 1)
} yield z
// → Set(2.0, 0.0, -2.0)           たどり着ける値の集まり。0 は1回
```

- List は「全ての道筋」を数える
- Set は「たどり着ける値」だけを集める

1つの for 内包表記の中で List と Set を混ぜることもできる

Rustでは

Rust の集合は HashSet（または順序付きの BTreeSet）

例

```rust
use std::collections::HashSet;

let zs: HashSet<i64> = [1i64]
    .into_iter()
    .flat_map(|x| [x, -x])            // f（√1 = 1 なので簡略化）
    .flat_map(|y| [y + 1, y - 1])     // g
    .collect();                       // HashSet に集めると重複が消える
// {2, 0, -2}
```

まとめ

| 型 | flatMap の「つなげる」 | 結果の意味 |
|---|---|---|
| List | 連結 `++` | 全ての道筋（順番・重複あり） |
| Set | 和集合 `∪` | たどり着ける値（重複なし） |
| Option | None なら止まる | あれば1個、なければなし |
