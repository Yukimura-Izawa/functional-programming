# 03 イミュータブルな値

## イミュータブルな値が必要な理由

純粋関数だけでは、状態が意図せず変化してしまう時がある

例えば
```java
planA = [Paris, Berlin, Kraków]
static List<String> replan(List<String> plan, String newCity, String beforeCity) {
    int index = plan.indexOf(beforeCity);
    if (index < 0) return plan;               // javaでは見つからなければ-1となる、そしてそのときそのまま返す
    List<String> replanned = new ArrayList<>(plan);
    replanned.add(index, newCity);
    return replanned;
}
```
これはもしも変更加えない時は値をそのまま返す。それではもしも以下を実行すると、
```java
List<String> planB = replan(planA, "Vienna", "Rome");
planB.add("Oslo");    
```  
これは planB だけ変えたつもりなのに、planA が変更を加えられてしまう。
replan 自体は純粋関数である。しかし、見つからないときは元のリストをそのまま返し（恒等関数のように振る舞う）、見つかったときはコピーを返す。呼び出し側はどちらが返ってきたか区別できないので、planB に add すると planA まで変わってしまう。
だからこそ値がイミュータブルであることが一つの解決策となる
(もう一つの解決策は見つからないときは Option で「なし」を返す)


## 補足
リファクタリング：プログラムの外部から見た挙動（動作結果）を変えずに、内部のコード構造を整理・改善する作業のこと
